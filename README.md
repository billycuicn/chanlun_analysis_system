# chanlun_analysis_system

# 中证1000缠论交易系统需求

> 定位：通过缠论来分析走势，并生成缠论的分析报告
> 核心思路：数据采集 → 画笔（TradingView） → 程序识别线段/中枢/买卖点 → 点击导出分析报告

## 一、系统目标

1. **打开系统时**，系统自动采集并补齐最新数据。数据为中证1000指数30分钟K线，至少800根K线
2. **画笔**：用户在 TradingView 图表上手工标注上升笔/下降笔，笔之间共用端点
3. **程序识别**：在笔的基础上，自动识别线段/中枢/买卖点，叠加显示在图表上
4. **点击导出**：点击报告生成按钮，生成结构化分析报告，推送至 Obsidian

---

## 二、数据规格

### 2.1 行情数据

- **品种**：中证1000（000852.sh）
- **周期**：30分钟K线
- **数据源**：新浪财经K线接口
  ```
  https://hq.sinajs.cn/list=sh000852
  ```
  参数 `scale=30` 表示30分钟周期。新浪K线为累加式返回，每次请求返回全部历史K线，每天数据会覆盖更新。
- **存储路径**：`/tmp/csi852_30min.csv`
- **字段**：时间, 开盘, 最高, 最低, 收盘, 成交量（共6列，逗号分隔）
- **最少K线**：800根（约16个交易日，覆盖3-5天趋势对比需求）
- **补齐逻辑**：每次运行从新浪拉最新K线，与本地CSV合并去重（按时间字段作key），同一时间点保留最新价

### 2.2 新浪API详解

**请求方式**：
```bash
curl -s "https://hq.sinajs.cn/list=sh000852" \
  -H "Referer: https://finance.sina.com.cn" \
  -H "User-Agent: Mozilla/5.0" | iconv -f GBK -t UTF-8
```

返回格式示例：
```
var hq_str_sh000852="2025-12-01 09:30,8200.5,8220.3,8195.0,8210.8,123456;2025-12-01 10:00,8210.8,8235.0,8205.0,8230.2,234567;..."
```
格式：`日期 时间,开,高,低,收,成交量`，每根K线用分号分隔。

**数据采集脚本** `chan_fetch.py`：
- 检查本地 `/tmp/csi852_30min.csv` 是否存在且K线数≥800
- 若不足800根，向新浪请求全部历史K线
- 若已存在800根+，请求当天最新数据（新浪返回全量），与本地合并去重后保存
- 采集完成后打印：`已采集 N 根K线，最新一根：YYYY-MM-DD HH:MM @ 价格`

## 三、工作流程（完整循环）

```
1. chan_fetch.py
   → 拉取新浪30分钟K线数据，补齐到800根+
   → 保存 /tmp/csi852_30min.csv

2. TradingView 图表
   → 加载 K线（通过插件或手动导入CSV）
   → 用户手工在图表上标注笔（上升笔/下降笔）
   → 笔之间共用端点（前一笔的终点 = 后一笔的起点）

3. chan_analyzer.py
   → 读取笔数据（从TradingView导出或共享文件）
   → 程序自动识别线段、中枢、买卖点
   → 结果叠加显示在 TradingView 图表上

4. chan_report.py
   → 点击报告生成按钮
   → 读取分析结果 JSON
   → 生成结构化分析报告
   → 推送至 Obsidian
```

**注意**：步骤2中用户手工画笔，步骤3中程序在笔的基础上自动识别线段/中枢/买卖点，两者协同完成缠论结构分析。

## 四、画笔规则（用户手工操作）

### 4.1 笔的定义

笔 = 连接两个相邻转折点的线段，每个转折点必须是**明显的高点或低点**。

- **上升笔**：起点是低点，终点是高点（价格向上）
- **下降笔**：起点是高点，终点是低点（价格向下）
- **笔的连续性**：前一笔的终点 = 后一笔的起点（共用端点）

### 4.2 画笔原则

- 笔须包含**至少5根K线**，否则不构成笔
- 忽略小幅次级波动（程序自动识别容易拆碎，用户凭经验将若干小波动归为一段）
- 关键位置可加标注：一卖/二卖/低点1/已结束/待确认 等
- 画笔是手工操作，程序不自动生成笔，只在用户画的笔基础上做分析

### 4.3 标注文件格式

从 TradingView 导出或程序读取的笔列表，格式如下（`/tmp/csi852_bi.csv`）：

```
序号,方向,起点时间,终点时间,K线数,起点价,终点价,标注
1,上,06-03 09:30,06-03 11:00,5,8200.5,8280.3,
2,下,06-03 11:00,06-04 10:00,8,8280.3,8150.8,低点1
3,上,06-04 10:00,06-04 14:00,9,8150.8,8235.0,
...
```

## 五、程序分析（chan_analyzer.py）

**触发**：用户画完笔后，运行 `python3 chan_analyzer.py`（手动运行或TradingView插件触发）

**输入**：`/tmp/csi852_bi.csv`（笔列表）

**输出**：
- `/tmp/chanlun/segments.json` — 线段列表
- `/tmp/chanlun/zhongshu.json` — 中枢列表
- `/tmp/chanlun/signals.json` — 买卖点列表

结果同时叠加显示在 TradingView 图表上。

### 5.1 线段识别

线段 = 连续3笔，且第1笔与第3笔有重叠区域

- **向上线段**：下-上-下组合，第1笔（下）与第3笔（下）必须有重叠区间，线段方向向上
- **向下线段**：上-下-上组合，第1笔（上）与第3笔（上）必须有重叠区间，线段方向向下

```
重叠判断逻辑：
笔1的高点 > 笔3的低点 → 有重叠
重叠区间 = [max(笔1低点, 笔3低点), min(笔1高点, 笔3低点)]
```

### 5.2 中枢识别

中枢 = 线段内部，连续3笔（不要求连续）重叠区域

- 在每个线段内，搜索有重叠的3笔组合
- 中枢区间：[ZD, ZG]，ZD=重叠区间低点（中枢底），ZG=重叠区间高点（中枢顶）
- 标注中枢类型：上升中枢 / 下降中枢

### 5.3 买卖点判断

**卖点（向上线段中的顶部信号）**：
- **一卖**：向上线段终点，价格创本线段内新高后回落
- **二卖**：向上线段内，回调笔（向下）的低点后反弹，反弹高点不创新高
- **三卖**：反弹不过二卖高点 + 后续跌破线段内前低

**买点（向下线段中的底部信号）**：
- **一买**：向下线段终点，价格创本线段内新低后回升
- **二买**：向下线段内，反弹笔（向上）的高点后回落，回落低点不创新低
- **三买**：回落不过二买低点 + 后续突破线段内前高

**买卖点状态**：
- 待确认：当前价格未确认突破/跌破
- 已确认：当前价格已触发
- 已失效：走势已离开，信号过期

### 5.4 趋势综合

综合多个线段+中枢，判断当前走势：
- 当前在哪个中枢区间内（震荡）
- 是否离开中枢：向上突破ZG 或 向下突破ZD
- 最近线段方向：判断短期方向（向上/向下/震荡）
- 结合近期3-5天结构，给出综合判断

## 十、关键价位跟踪

每份报告必须列出：

- 最近低点：精确价格 + 时间
- 最近高点：精确价格 + 时间
- 关键中枢上沿（ZG）：精确价格
- 关键中枢下沿（ZD）：精确价格
- 买卖点价位：精确价格 + 状态（待确认/已确认/已失效）

---

## 十一、边界情况处理

- **K线不足800根**：采集脚本报错退出，提示"K线数量不足，需先采集数据"
- **笔数量 < 3**：分析引擎提示"笔数量不足（X笔），至少需要3笔才能识别线段"
- **线段数量 = 0**：报告"当前笔尚未构成线段，继续观察"
- **无重叠区域**：跳过后续判断，不生成线段/中枢
- **买卖点触发**：已触发的买卖点标记为"已触发"，未触发的标记"待确认"，已过期的标记"已失效"
